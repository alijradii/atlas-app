# Atlas Pearl · study workspace

Atlas is a Bun/Next.js frontend with a Python/FastAPI backend, using the supplied Pearl design. The working app includes private study, files, account controls and connected teacher/student/advisor/parent workflows. Sign in to `/workspace`, open `/files` to upload materials, or `/study` to learn from approved transcripts with cited Gemini answers. Fixture-backed `/preview/*` routes are disabled in normal builds and available only to the explicit browser test harness.

See [school workflows and provisioning](docs/SCHOOL.md), [study and imports](docs/STUDY.md), [private files](docs/MEDIA.md), and [account controls](docs/ACCOUNT.md). Access depends on accounts, roles and explicit sharing, never being on a school network.

Real accounts and preview personas use the same Pearl sidebar, home layout, task
cards and prompt dock. Sign-in opens the real Home; **Files & recordings** and
**Study with agent** stay in that sidebar throughout uploads, transcript review and
cited conversations. Examples use fixtures; authenticated screens use permitted API
records. Lesson cards, chat and advisor screens also reuse the original screen
components. Local demo accounts can be populated with persisted examples using
[the guarded demo tool](docs/DEMO_ACCOUNTS.md).

## Assistant and demo access

The assistant stays available across authenticated screens, keeping its draft and
minimized state during navigation. Questions and suggestion buttons call Gemini;
UI help loads role-aware instructions through the real read-only MCP server and
highlights the relevant control. See [UI_ASSISTANT.md](docs/UI_ASSISTANT.md).
Study uses the same dock: start talking immediately, or select lesson sources for cited answers.
Window/workspace switches refresh authorization in the background without blanking
same-account content. All text areas grow automatically to a capped height.

The four local database-backed demonstration accounts use `student`, `teacher`,
`advisor`, and `parent` after the guarded operator migration. They retain their saved
work and normal session/role authorization; they are not runtime hardcoded users.
[DEMO_ACCOUNTS.md](docs/DEMO_ACCOUNTS.md) describes population and login migration.
Public fake-account buttons have been removed. The release gates in
[SECURITY.md](docs/SECURITY.md) still apply before public deployment.

Pitch framing, demo narration and corrected technical labels are in
[DEMO_BRIEF.md](docs/DEMO_BRIEF.md).

## Retained infrastructure

- Bun 1.4.2 / Next.js / TypeScript frontend in `apps/web`, Pearl tokens and owned shadcn UI in `packages/ui`.
- Python 3.14 / uv / FastAPI backend in `apps/api` and `packages/backend`.
- PostgreSQL, Alembic migrations, Redis, Celery worker and periodic media cleanup.
- Server-side sessions, password hashing, request-origin/CSRF checks, login throttling and explicit installation state.
- Private local/R2 storage adapters, checksums, quarantine, scanner integration and per-user file authorization.
- Generated OpenAPI contracts, CI, Docker/Caddy deployment templates and release gate.
- Authenticated study API, durable extraction/transcription and ingestion/answer jobs, reviewable transcripts, conversation history and explicit sharing.
- Real lesson publishing, assignments/submissions/feedback, private advisor messages and human proposal approvals.
- Teacher-managed events, explicit peer-interest activity requests and evidence-gated AI suggestions; students review and share exploration reports with linked adults.
- Role-specific Teaching, Family and Advisor assistant screens using the persistent interface assistant; student Study remains dedicated to learners.
- Password changes with session rotation and sign-out-other-sessions controls.
- Separate Python 3.12 RAG service with Milvus Lite, Gemini embeddings and hybrid retrieval; Gemini answers are generated by the Python application backend.
- Optional ClamAV and Mailpit services; the older internal AI health-only placeholder is not the study inference service.

## Start locally

Requirements: Bun 1.4.2, Python 3.14, uv 0.11.19, Docker Compose. Document/recording conversion also needs `pdftotext`/`pdfinfo` (Poppler), `ffmpeg`/`ffprobe`, and Linux `prlimit` (util-linux); these are installed by the Python Dockerfile and CI.

```sh
make bootstrap
make dev
```

In another terminal, create an account (password is prompted, never passed on the command line):

```sh
make create-user LOGIN=you@example.com NAME="Your Name"
```

Open http://localhost:3000 for the landing page, `/login` for sign-in, to access your saved workspace. `/workspace`, `/files`, `/study` and `/account` require a real session. Sign-in opens Workspace; explicit `next=files`, `next=study`, `next=account` redirects are supported. Assign school roles and student relationships with the commands in [SCHOOL.md](docs/SCHOOL.md); unassigned accounts can still use private files and Study. Existing active accounts still work after migration. New installations require the local account command; there is no public signup, automatic default account, setup wizard or persona-login shortcut. The explicitly provisioned local demo accounts use the same sign-in form. To reset a password and revoke all sessions:

```sh
uv run --frozen python -m school2036.operator reset-password --login you@example.com
```

Development listeners bind to localhost. `make dev-full` also starts the scanner, local mail capture and AI placeholder. Set `SCHOOL_SCANNER_HOST=127.0.0.1` in your private `.env` and restart API/worker to enable binary-file verification. Without a scanner, development accepts plain UTF-8 text only; documents, images and recordings remain unavailable until scanning succeeds. `make dev` also starts the scanner when `SCHOOL_SCANNER_HOST=127.0.0.1`. Production always requires scanning and private R2.

## Study at home

Configure the server-only provider keys in `.env`, then run `make rag-install` once to install the separate Python 3.12 retrieval runtime. `make dev` starts it when both keys are configured. An existing compatible environment can be selected with `SCHOOL_RAG_PYTHON`. Open `/study`, add a text/Markdown transcript, wait for preparation, and select one to eight ready lessons for a conversation. Source quotations accompany answers. Sharing is explicit by an existing account login; preview roles never grant access.

You can also upload PDF/DOCX documents or audio/video clips in Files, choose **Use for study**, then review and approve the extracted transcript in Study. Recordings are limited to 20 minutes and transcription uses Gemini; scanned PDFs need a supplied text transcript. See [the study setup and controls](docs/STUDY.md). The default RAG budget is $1; answer generation has separate provider charges.

## Files

Uploads are private to their owner: documents/images up to 10 MiB, audio/video up to 50 MiB and 500 MiB per account by default (existing environment overrides remain in force). The UI creates a staging upload, sends bytes, requests verification and polls status. Only accepted files can be downloaded. Deletion is immediate for access and asynchronous for stored bytes, so keep the worker and beat running. See [media configuration](docs/MEDIA.md).

## Existing data and migrations

No existing database, volume, `.env`, or uploaded object is reset by this source change. Historical migrations remain immutable so existing databases can advance safely; new personal files use a separate `personal_file` table. Legacy course attachments are preserved but are not exposed through the new personal-files API. Retired domain tables are retained for future reviewed migration; do not drop them or use automatic migration generation to remove them.

Documents in `docs/archive/` are historical references, not implemented capabilities or the current rebuild scope. A private source snapshot of the pre-reset working tree was saved at `/tmp/school2036-before-reset.tar.gz` during this change; it excludes ignored files and is temporary, not a database backup.
